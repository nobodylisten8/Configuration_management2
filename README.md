# Dependency Graph Visualizer

Инструмент визуализации графа зависимостей для менеджера пакетов.

## Этап 1: Минимальный прототип с конфигурацией

Реализовано минимальное CLI-приложение, которое принимает параметры через опции командной строки, валидирует их и выводит конфигурацию в формате ключ-значение.

### Настраиваемые параметры

| Параметр | Описание | Обязательный | По умолчанию |
|----------|----------|--------------|--------------|
| `--package` | Имя анализируемого пакета | Да | — |
| `--repo-url` | URL репозитория или путь к файлу | Да | — |
| `--test-mode` | Режим работы с тестовым репозиторием | Нет | `False` |
| `--version` | Версия пакета | Нет | `latest` |
| `--output-file` | Имя файла с изображением графа | Нет | `graph.png` |
| `--ascii-tree` | Вывод зависимостей в формате ASCII-дерева | Нет | `False` |

### Установка и запуск тестов

```bash
pip install pytest
python -m pytest tests/
```
## Этап 2: Сбор данных

Реализована основная логика получения данных о зависимостях из репозиториев Alpine Linux в формате APK. Сбор выполняется без использования сторонних библиотек и менеджеров пакетов.

### Как это работает

1. По указанному `--repo-url` скачивается файл `APKINDEX.tar.gz`.
2. Архив распаковывается в памяти через `tarfile` + `io.BytesIO`.
3. Извлекается текстовый файл `APKINDEX`.
4. Файл парсится в список пакетов с полями `name`, `version`, `dependencies`.
5. Находится пакет по имени и версии.
6. Выводятся его прямые зависимости.

### Примеры использования

**Получение зависимостей реального пакета:**
```bash
python -m src.main --package alpine-baselayout --version 3.6.5-r0 --repo-url https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64/
```

**Пакет с одной зависимостью:**
```bash
python -m src.main --package busybox --version 1.36.1-r31 --repo-url https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64/
```

**Чтение из локального файла:**
```bash
python -m src.main --package my_pkg --version 1.0.0 --repo-url /path/to/APKINDEX
```

### Обработка ошибок

**Пакет не найден:**
```bash
python -m src.main --package nonexistent --version 1.0 --repo-url https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64/
```

**Неверный URL (404):**
```bash
Error: HTTP Error 404: Not Found
```
## Этап 3: Основные операции

Реализовано построение графа зависимостей с учетом транзитивности
алгоритмом **BFS с рекурсией**. Корректно обрабатываются циклические
зависимости. Поддержан режим тестирования с загрузкой графа из файла.

### Как это работает

1. В режиме тестирования (`--test-mode`) граф загружается из текстового файла.
2. Формат файла: каждая строка `PACKAGE: DEP1 DEP2 DEP3`.
3. Строится полный граф зависимостей начиная с заданного пакета.
4. Алгоритм **рекурсивного BFS** обходит все транзитивные зависимости.
5. Детектируются циклические зависимости.
6. Выводится граф, циклы и все транзитивные зависимости.

### Примеры использования

**Тестовый режим (простой граф без циклов):**
```bash
python -m src.main --package A --repo-url tests/test_data/simple_graph.txt --test-mode
```
**Тестовый режим (граф с циклом):**
```bash
python -m src.main --package A --repo-url tests/test_data/cyclic_graph.txt --test-mode
```
**Тестовый режим (сложный граф):**
```bash
python -m src.main --package A --repo-url tests/test_data/complex_graph.txt --test-mode
```
## Этап 4: Дополнительные операции

Реализован вывод порядка загрузки зависимостей с помощью алгоритма
топологической сортировки (алгоритм Кана).

### Примеры использования

**Порядок загрузки (граф без циклов):**
```bash
python -m src.main --package A --repo-url tests/test_data/simple_graph.txt --test-mode --load-order
```
**Вывод:**
```text
Load Order:
  1. D
  2. E
  3. B
  4. C
  5. A
```
**Порядок загрузки (граф с циклами):**
```bash
python -m src.main --package A --repo-url tests/test_data/cyclic_graph.txt --test-mode --load-order
```
**Вывод:**
```text
Load Order:
  (cannot determine due to cyclic dependencies)
```
**Сравнение с реальным менеджером пакетов**

При наличии циклических зависимостей топологическая сортировка
невозможна, и наш инструмент честно сообщает об этом. Реальный
менеджер пакетов Alpine Linux (apk) в таких случаях пытается
разрешить зависимости жадным алгоритмом: он устанавливает пакеты
по мере их появления в списке, игнорируя обратные зависимости.
Это может приводить к ситуациям, когда пакет устанавливается до
своей зависимости, что вызывает ошибки при конфигурации. Наш
подход более консервативен и безопасен — он явно указывает на
проблему, вместо того чтобы молча её обходить.
